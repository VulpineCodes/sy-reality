# Sy-Reality!

A VR karaoke project for Meta Quest 3, built in Unity with C# and OpenXR.
The goal is a stage performance with lyrics timed to the music. This
repository holds the foundation for that goal. It does not yet hold a
working headset build.

The deterministic timing core is implemented in pure C# and unit tested.
The Unity layer that binds it to the engine is written but has never been
opened in Unity or run on a headset. There are no screenshots or gameplay
footage yet, and none are claimed. See [STATUS.md](STATUS.md) for the exact
verified and unverified breakdown. Claims in this README follow it.

## Why it is built this way

Karaoke timing fails when the clock and the lyric lookup disagree, so this
project keeps everything deterministic in a pure C# core with no UnityEngine
dependency:

- Sync is a pure function of time. The engine is stateless, so seek and pause cannot desynchronize it.
- The audio clock is the reference. The playback clock measures drift against the AudioSource every frame and snaps back past a 0.15 second threshold. This threshold is set in code and has not been tuned on a headset.
- Flow is an explicit state machine. Invalid transitions are rejected and logged instead of being silently absorbed.
- Songs are data. Songs are JSON with per line and per syllable timings, so new songs need no code. Environments are ScriptableObject data too.

## Song data format

Songs live in `Assets/SyReality/Resources/Songs/*.json`:

```json
{
  "id": "twinkle-twinkle-little-star",
  "title": "Twinkle Twinkle Little Star",
  "artist": "Traditional",
  "rightsNote": "Traditional nursery rhyme, public domain.",
  "durationSeconds": 36.0,
  "difficulty": 1,
  "audioFile": "",
  "lines": [
    { "start": 0.0, "end": 6.0, "text": "Twinkle, twinkle, little star",
      "syllables": [ { "start": 0.0, "end": 0.857, "text": "Twin" } ] }
  ]
}
```

`audioFile` names a file in `Assets/StreamingAssets/Audio/`. Add only audio
you have a right to use. An empty value means silent test mode. Syllable cues
are optional. Without them, highlighting interpolates linearly across the
line.

## Setup

Requirements: Unity 6000.3 (the project is pinned to 6000.3.23f1) and a Meta
Quest 3 for device builds. Editor play mode does not need a headset.

Headless core tests first. These need a .NET 8 SDK and cover the core logic
only, not the Unity layer:

```bash
dotnet build tools/CoreTests && dotnet tools/CoreTests/bin/Debug/net8.0/CoreTests.dll
```

Last run here: 30 of 30 passed on 2026-10-28. See STATUS.md for the exact
command environment used in this workspace.

First run in Unity (not yet done from this repository):

1. Clone, then open the folder in Unity Hub with Unity 6000.3.
2. Let packages resolve (OpenXR, XR Interaction Toolkit, Input System,
   TextMeshPro, Test Framework, see `Packages/manifest.json`). Import TMP
   Essentials if prompted.
3. Menu **SyReality, Build MainStage Scene**. This generates the scene, the
   three environment profiles, and the song button prefab. Follow the short
   checklist in `Assets/Scenes/README.md`.
4. Project Settings, XR Plug-in Management, enable OpenXR (Android) with the
   Meta Quest Touch interaction profile.
5. Press Play. The expected flow is Lobby, song select,
   *Twinkle Twinkle Little Star*, countdown, then lyrics advancing in silent
   test mode. This flow has not been run yet.
6. Tests: Window, General, Test Runner, EditMode, Run All. This in editor
   run has not happened yet either.

## Content and licensing

No copyrighted recordings or lyrics are bundled or distributed. Bundled
songs are public domain or original placeholders, and every song file
carries a `rightsNote` stating its basis. Users add their own licensed audio
under `StreamingAssets/Audio`.

## Known limitations

- Nothing in the Unity layer has been executed yet. The first in editor run
  is the Phase 0 exit criterion in STATUS.md.
- The XR rig in the generated scene is a placeholder. XRI's XR Origin
  replaces it for device work.
- Package versions in the manifest are initial pins to confirm on first
  import in Unity 6000.3.
- No pitch detection, recording, or multiplayer. See the roadmap for how
  each would be added.
