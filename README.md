# Sy-Reality!

A VR karaoke experience for Meta Quest 3: step onto a stage, pick a song, and
perform it in an immersive environment while lyrics stay locked to the music.

Sy-Reality! began as Franklin Udensi's VR karaoke project at Vanderbilt
(Unity/C#, Meta Quest) and is being rebuilt here as a portfolio-grade
vertical slice — modular, data-driven, and tested — rather than a one-off
scene.

> **Status:** foundation. The deterministic core (lyric sync, playback clock,
> state machine) is implemented and unit-tested; the Unity project has **not
> yet been opened in Unity or run on a headset** from this repository. See
> [STATUS.md](STATUS.md) for the exact verified/unverified breakdown — claims
> in this README follow it.

## Why it's built this way

The interesting engineering in karaoke is timing. Sy-Reality! puts everything
deterministic in a **pure C# core with no UnityEngine dependency**:

- **Sync is a pure function of time** (stateless engine) — seek and pause
  can't desynchronize it.
- **The audio clock is the truth** — the playback clock measures drift
  against the AudioSource every frame and snaps back past a 0.15s threshold.
- **Flow is an explicit state machine** — invalid transitions are rejected
  and logged, not silently absorbed.
- **Songs are data** — JSON with per-line and per-syllable timings; new songs
  need no code. Environments are ScriptableObject data too.

## Song data format

Songs live in `Assets/SyReality/Resources/Songs/*.json`:

```json
{
  "id": "twinkle-twinkle-little-star",
  "title": "Twinkle Twinkle Little Star",
  "artist": "Traditional",
  "rightsNote": "Traditional nursery rhyme — public domain.",
  "durationSeconds": 36.0,
  "difficulty": 1,
  "audioFile": "",
  "lines": [
    { "start": 0.0, "end": 6.0, "text": "Twinkle, twinkle, little star",
      "syllables": [ { "start": 0.0, "end": 0.857, "text": "Twin" } ] }
  ]
}
```

`audioFile` names a file in `Assets/StreamingAssets/Audio/` — **your own
licensed audio**; empty means silent test mode. Syllable cues are optional;
without them, highlighting interpolates linearly across the line.

## Setup

Requirements: **Unity 6000.3** (project is pinned to 6000.3.23f1), a
**Meta Quest 3** for device builds (editor play mode works without one).

1. Clone, open the folder in Unity Hub with Unity 6000.3.
2. Let packages resolve (OpenXR, XR Interaction Toolkit, Input System,
   TextMeshPro, Test Framework — see `Packages/manifest.json`). Import TMP
   Essentials if prompted.
3. Menu **SyReality → Build MainStage Scene** — generates the scene, the
   three environment profiles, and the song-button prefab. Follow the short
   checklist in `Assets/Scenes/README.md`.
4. Project Settings → XR Plug-in Management → enable OpenXR (Android),
   Meta Quest Touch interaction profile.
5. Press Play: Lobby → song select → *Twinkle Twinkle Little Star* →
   countdown → lyrics advance in silent test mode.
6. Tests: Window → General → Test Runner → EditMode → Run All.
   Headless alternative (core logic only):
   `dotnet build tools/CoreTests && dotnet tools/CoreTests/bin/Debug/net8.0/CoreTests.dll` (NUnitLite) with any .NET 8 SDK.

## Content & licensing policy

No copyrighted recordings or lyrics are bundled or distributed. Bundled songs
are public domain or original placeholders, and every song file carries a
`rightsNote` stating its basis. Users add their own licensed audio under
`StreamingAssets/Audio`.

## Known limitations

- Nothing in the Unity layer has been executed yet — first in-editor run is
  Phase 0's exit criterion (STATUS.md tracks it).
- XR rig in the generated scene is a placeholder; XRI's XR Origin replaces
  it for device work.
- Package versions in the manifest are initial pins to confirm on first
  import in Unity 6000.3.
- No pitch detection, recording, or multiplayer — see the roadmap for how
  each would be added honestly.
